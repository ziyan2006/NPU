# 扩充模型选择验证与同条件频带对照

日期：2026-10-01。范围：离线 FP32 模型研究，不改现行板端权重、不生成新上板镜像、不写 SD。

后续更新：本报告提出的弱人声波形目标加权对照现已完成，200 步及 145 段回归仍无合格候选，训练误差归因和下一步见 [报告 17](17_weak_vocal_objective_probe.md)。下文保留本次频带对照的原始结果和当时计划。

## 为什么重新做对照

前面的内部验证只取 MUSDB、MIR-1K、纯器乐各 3 首，每首 1 个窗口，实际计分共约 13.1 秒。它既没有覆盖全部预留曲目，也没有专门检查弱人声，容易因纯器乐改善而选到“保留更多声音，但消人声未变好”的候选。

另外，报告 13 的残差训练使用 `0.6 真值频带损失 + 0.4 教师频带损失 + 波形损失`，报告 15 的 mel_unique 使用 `1.0 真值频带损失 + 波形损失`。两者不能直接当作只改变频带布局的对照。本次补上 **legacy_log 真值-only 对照组**，不通过修改旧脚本或旧结果来消除这项差异。

## 新的开发验证集

- 沿用既有歌曲级隔离：MUSDB 19 首、MIR-1K 9 首、纯器乐 3 首，合计 **31 首**，不从最终留出池借歌来选检查点。
- 每首固定 3 个不同起点（可裁剪范围的 10%、50%、90%），共 **93 个原始窗口**。
- 28 首有人声曲目分别加入同窗口人声衰减 12 dB 的版本，伴奏保持不变；包含重混版本共 **177 段**。
- 44.1 kHz，FFT1024/hop256；每段 89,856 个样本，评分只用 `[25,088, 89,344)`，排除上下文预热及 STFT 边界。
- 原始窗口计分累计约 **135.5 秒**；计入弱人声版本约 **257.9 秒**。窗口可能重叠，重混不是新录音，不能说有 177 个独立样本。

全套窗口的位置、增益、音频张量 SHA-256 和评分区间在 `selection_suite.json` 固定。预训练权重可能见过这些内部保留曲目，故这是**开发验证**，不是新盲测。OnAir 只有 2 首训练曲目，本次没有再拆掉其中一首；它原有的留出曲目仍只作回归检查。弱人声重混也不能代替真实电子人声的验证数据。

## 评分与选择规则

每个窗口输出：人声/伴奏 SI-SDR、尺度相关的 error-SNR、联合拟合的伴奏保留系数与剩余人声系数。先对同歌的窗口平均，再按歌曲、数据域平均，避免长曲和纯器乐数量主导选择。

其中 `输出伴奏 ≈ ca × 真伴奏 + cv × 真人声 + 拟合残差` 的 `ca/cv` 只是联合最小二乘诊断，不是独立提取出的干扰声，也不是听感分数。人声和伴奏相关性太高时不强行给出系数。

训练前固定的开发选择门：

1. MUSDB/MIR 的原始、弱人声 4 个域，人声 error-SNR 各自退化不得超过 0.25 dB。
2. 纯器乐的伴奏 error-SNR 退化不得超过 0.25 dB。
3. 各人声域的拟合伴奏保留系数下降不得超过 0.03；剩余人声绝对系数增加不得超过 0.25 dB，4 域平均不得增加。
4. 4 个人声域等权平均的 error-SNR 增益至少 0.15 dB；只在合格点中按该增益排序。

这组门槛是开发阶段的保守筛选规则，不是经听感标定的产品验收标准。没有合格点时记录 **selected checkpoint = NONE**，不能自动把“最不差”的候选称作升级。纯器乐分数再好也不能独自满足人声改善门。

## 同条件训练

两组均从冻结的 824,900 参数 bott2 模型起跑；同种子、同歌曲池、同裁剪/增益/左右交换、同 200 步、同新建 Adam、同学习率 `5e-6` 预热/余弦计划、同 complement 频带目标及混音能量归一化波形损失，**两组都没有教师训练损失**。每一步对原始波形批次保存 SHA-256，逐步比较两组是否完全相同。

区别是分析/合成频带布局及其匹配的低频保护索引：`legacy_log` 的 LF250 清零 44 带，`mel_unique` 清零 6 带。名义保护频率相同，离散频带映射不同。因此这是“频带表示及匹配重建/保护”的 warm-start 适配对照，不是从头训练的架构上限对照，也不能分离教师损失的贡献。

首次整批执行在本机并发 GPU 占用较高时异常缓慢，已停止自己的训练进程，结果保留在 `results/layout_control_20261001/`，标记为 aborted。有效实验改用 microbatch=1，6 个样本的损失和梯度按样本数累积后，统一裁剪并更新一次 Adam。无 BatchNorm/Dropout；合成测试已验证整批/累积损失和梯度在浮点误差内一致。没有关闭用户的其他 GPU 程序。

有效产物目录：`results/layout_control_microbatch_20261001/`。CUDA 确定性算法开启，TF32 关闭；相同实验内两组执行策略一致。并不承诺不同硬件/PyTorch 版本字节级复现。

这轮更明确地定位了一个问题：**当前目标可以通过少误删乐器来改善重建误差，却没有保证更少的剩余人声**。新增选择规则使这种候选不再被当作“消人声改善”。单一短训练预算仍不足以确定最终收敛质量。

纯器乐 error-SNR 分别为 +2.627 / +0.035 dB。legacy_log 在原有的临时 FP32 gate **通过**，mel_unique **未通过**；但是前者在**新的开发选择门未通过**，而且弱电子乐暴露了伴奏损伤，故本轮仍无部署候选。旧门通过只代表旧 smoke 条件，不推翻新的人声残留检查。

MUSDB 人声 error-SNR 的逐歌增益：legacy_log 平均 **+0.142 dB**，描述性歌曲 bootstrap 区间 `[+0.069, +0.216]`；mel_unique 平均 **-0.684 dB**，区间 `[-1.053, -0.377]`。MIR 的 legacy_log 为 **-0.031 dB**，区间 `[-0.085, +0.015]`，没有显示稳定的重建提升。这里的区间只描述已用过的这些歌曲，不能当作独立泛化/显著性证明。

电子乐分曲进一步说明为什么不能只看域均值：

- DNB 原始：冻结基线的人声 / 伴奏 SI-SDR 是 **-8.895 / 12.650 dB**；legacy_log 末步是 **-8.902 / 12.479 dB**，人声没有实质改善，伴奏更差。mel_unique 是 **-10.350 / 12.992 dB**，伴奏略好但人声估计更差。
- DNB 弱人声：剩余人声绝对拟合系数从基线 **0.833** 到 legacy_log **0.810**，但伴奏 SI-SDR **17.499 → 16.479 dB**，损伤增加；mel_unique 剩余人声系数 **0.895**，伴奏反而更好。两者都不是明确的消声/保真双赢。
- Angelsaint 原始：legacy_log 人声 / 伴奏 SI-SDR 改善约 **+0.392 / +0.221 dB**，但剩余人声系数 **0.340 → 0.378**；改善的一部分来自减少误删，不等于消声更彻底。

以上拟合系数不直接等于听感，更不能替代重新试听与实板验收。电子曲目只有两首，暂不作整体 EDM 结论。

## 下一轮应解决什么

1. **先保留 legacy_log 与现有模型图。** 同预算旧频带更稳；尚无依据用更大的网络或新布局承担额外适配/硬件成本。
2. **固定新选择集后，单独比较弱人声目标。** 优先测试有混音能量下限的“人声能量归一化波形误差”，提高弱人声样本在损失中的权重，同时保留纯器乐和伴奏保真约束。这是待验证方案，不提前承诺改善。
3. **再单独测试相位一致的掩码目标。** 现行频带目标是幅度比例，产品重建却只能用混音相位上的实值 `[0,1]` 掩码；目标/重建不完全一致。不能同时改布局、损失和目标后只归因于其中一项。
4. **补充新的电子人声曲目并预留真正独立验收集。** 目前两首旧反例只能说明已有问题，不足以用来认证修复；歌曲/跨库同曲隔离仍必须在训练前固定。

这些模型目标改动可以保持相同参数量和板端卷积图；确认浮点收益后仍须进行完整整数误差、保留上下文及实板听感验收。未开始本节的新目标训练，也没有在回归曲目上挑模型。

## 回归检查边界

`121_evaluate_layout_control.py` 比较两组相同 **最终第 200 步**，不利用回归成绩回头挑步数。重用已有 143 段/78 首开发回归套件，另加两首 Cambridge 电子乐的人声 -12 dB 重混。它不是新盲测，Demons 的参考来自教师也不是独立真值。长音频推理按 256 帧分块，每块保留 128 帧历史且保持 stride 相位，STFT/iSTFT 连续；测试验证与整段 bott2 图输出一致，这不是旧板端的短块清空历史方式。

按歌曲配对差异进行描述性 bootstrap；少于 5 首的域不报总体置信区间。该区间不修正反复查看数据、跨曲相关性或预训练暴露，不可用作最终显著性/泛化证明。电子乐只有 2 首，弱人声重混不能增加独立歌曲数。
