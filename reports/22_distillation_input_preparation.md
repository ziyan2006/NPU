## 当前可执行部分

`136_prepare_distillation_data.py` 已能核验已完成的整首标签，并提供可恢复的裁剪接口：

- 原 MP3 **完整解码并核对封存 PCM 指纹**，不使用近似 MP3 时间跳转作训练对齐。
- CPU 缓存默认最多一首混音；对两个 FLOAT32 stem 按样本位置 seek，避免每个裁剪
  都载入整首分轨。原文件/标签先哈希，迭代中检测文件变化，不默默接受新版本。
- 每段 256 计分帧 + 96 预热帧，共 89,856 样本；STFT 得到 352 帧，满足当前图的
  8 帧倍数。起点限制在 8×256=2,048 样本网格，不在每个训练计分段重置上下文。
- 波形计分区间 `[25088:89344]`，约 1.457 s；保留预热，屏蔽段边缘与整首源轨两端
  0.25 s。太短的歌曲或越界裁剪直接拒绝，不补零冒充完整上下文。
- 歌曲等概率采样；由 seed/cursor 决定曲目、起点及 -6～+3 dB 的共同增益。
  增益仅根据混音峰值和抽样决定，三份波形共用，混音峰值 <=0.95，标签不独立归一化
  或削波。输入身份不依赖教师目标，便于两臂使用相同输入。
- sampler state 保存快照绑定、seed 和 cursor；恢复数据/标签/代码改变时拒绝。
  配对检查要求混音实际样本一致，不只看文件名或抽样 seed 相同。

当前快照仅供 `purpose="cpu_audit"`。默认训练用途会拒绝；样本仍为
`training_eligible=false`。后续须审核标签并实现独立批准的训练导入，不把技术检查
当作人声/乐器标注质量认证。

真实 CPU 检查固定取清单前两首已完成歌曲，不按教师质量挑例子。8 次确定性裁剪后
保存 sampler cursor，验证下一段恢复后的混音、人声和伴奏逐样本相同。
前端形状为 **`[1,2,513,352]`**，STFT/iSTFT 最大绝对重建误差 **2.384e-7**。
再次从保存文件重跑审查，两份 `cpu_audit*.json` 字节哈希相同。
这是输入/前端和采样恢复检查，**不是新训练器的 optimizer 恢复、模型拟合或音质验收**。

| 伪标签曲目 | 固定 seed 从已封存 275 首候选选 24 首，名单写入快照；不根据学生或教师质量分数选择 |

| 监督 | 两臂都用 script126 的产品路径 waveform L1 + complex L1，不用旧频带掩码目标 |
| 预算 | Adam 1e-4、100 步 warm-up、余弦至 1e-5、梯度裁剪 3、microbatch=1，上限 10,000 更新 |
| 检查 | 每 250 更新验证；至少 2,000 更新后才考虑早停；共享停止步数及曝光预算 |
| 恢复 | 两臂各自保存模型、Adam、CPU/CUDA RNG 和输入 cursor；不能只重载权重冒充续训 |
| 选择 | 保留 script119 的既有人声/伴奏/纯器乐门槛；无合格 checkpoint 则 NONE |

旧缓存主要是频带掩码，不能当作同输入的原始波形参考；旧 45 s 试验 MP3 解码还
经过 PCM16 WAV，与本批 FLOAT32 完整输入不同。必须在当前 GPU 分轨完成后，
为固定 24 首重新生成匹配的 HTDemucs 波形标签，不能直接拼旧缓存做“公平对照”。

这 24 首合计 **5,417.217 s / 1.505 h**；新增两路旧教师标签含余量预算约
**4.205 GB / 3.916 GiB**。不用在 D 盘再存一份约 44 GiB 的全库旧教师标签。
生成前仍须重新检查磁盘预算。24 首对照只回答固定数据曝光下的教师变化，后续
扩至全部 275 首是独立的数据规模实验，不能混作同一归因结论。

不对两臂各自的人声估计做 -12 dB 重混：这会使输入本身不同，无法单独归因于教师。
弱人声开发评价继续使用既有真分轨重混及四域指标，MP3 伪标签不是最终真值。
