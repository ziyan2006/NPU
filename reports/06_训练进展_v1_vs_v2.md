## 0. 摘要

| 问题 | 答案 |
|---|---|
| 上一轮 6000 步为什么走平？ | **过拟合**，不是步数不够。train/val 损失差 2.4 倍，val 从第 500 步起就没再动过。 |
| 数据量 ×8.1 有用吗？ | **有用。** 过拟合基本消失（差距 2.4× → 1.4×），人声分离质量确实变好。 |
| 好多少？ | 在**同一批留出曲目**上，中位提升 **+0.55 dB / 5/8 变好**；只看**真正含人声**的片段，中位 **+0.85 dB**、均值 **+1.57 dB**，**3/3 全部变好**。（上限 +9.87 dB，见报告 03） |
| 现在还能听吗？ | 能出声、不是静音、电平正确，但离"按键产品可用"还差得远。 |
| 下一步的第一优先级？ | **不是加算力、不是加步数，是筛训练窗口。** 本轮发现 House/EDM 曲目里人声占比极低，随机截取的 30 秒窗口一大半根本没有有效人声（见 §5）。 |

> ⚠️ **两个数字不能相减**：v1 和 v2 的 val log-L1 是在**不同的验证集**上算的（3 首 vs 22 首），
> 它们的差值没有意义。本文所有结论都来自 §4 的同批 A/B 和 §2 的同轮内诊断。

## 1. 本轮做了什么

只改了一个自变量：**训练数据的量**。

| | v1（上一轮） | v2（本轮） |
|---|---|---|
| 曲目数 | 30 | **220** |
| 每首时长 | 30 s | 30 s |
| 唯一音频 | 900 音频秒 = **15.0 分钟** | 6600 音频秒 = **110.0 分钟** |
| 教师伪标签耗时 | 53.0 s @17.0 音频秒/s | 430.5 s @15.33 音频秒/s |
| 训练步数 | 6 000 | **15 813**（撞时间预算，非收敛） |
| 训练投入音频量 | 142 665 音频秒（39.6 h）≈ **158 遍** | 375 989 音频秒（104.4 h）≈ **57 遍** |
| 训练吞吐 | 411.5 音频秒/s | 368.6 音频秒/s（含每 100 步一次验证） |
| 墙钟总计 | 约 7 分钟 | **24 分 22 秒** |

架构、损失、优化器、超参、crop、batch **一行没动** —— 0.5297 M 参数、1.226 GMAC/音频秒、
128 频带的 FPGA 规格保持冻结。这一轮的作用是把"是数据的问题"这个假设证实或证伪。

训练吞吐下降（411.5 → 368.6）是验证频率变高导致的：v1 每 50 步验证一次 4 个 batch，
本轮每 100 步验证 8 个 batch，纯训练速率其实仍是 ~370 音频秒/s。

## 2. 诊断：上一轮是过拟合，不是欠训练

同一轮内部的 train/val 差值是自洽的，可以直接读：

取各自**最后 10 次记录的平均值**（单点比值受噪声影响太大）：

| | v1（最后 10 次，至第 6000 步） | v2（最后 10 次，至第 15800 步） |
|---|---|---|
| 训练 log-L1 | 0.7122 | 0.8769 |
| 验证 log-L1 | 1.6938 | 1.2310 |
| **差距** | **2.38 ×** | **1.40 ×** |

v1 的验证损失轨迹尤其说明问题：**第 500 步就已经是 1.6717，到第 6000 步是 1.6816**
（单点比值 2.71×）。后面 5500 步完全没有产生泛化收益，全部算力都变成了对 15 分钟素材的记忆。

v2 把差距压下来后，train 与 val 仍在同步下降，说明还有余量 —— 所以撞到时间预算才停，
而不是收敛停。

## 3. 本轮的直接结果

| 指标 | v1（6000 步） | v2（best-val 权重） | 说明 |
|---|---|---|---|
| 验证 log-L1 | 2.72 → 1.68 | **2.475 → 1.296** | ⚠️ 验证集不同，两列不可比 |
| 掩码预测 std | 0.2270 | **0.2458** | 未塌陷 |
| 掩码均值（预测 / 目标） | 0.25 / 0.06 | **0.2275 / 0.1610** | ⚠️ 见下 |
| 掩码 >0.5 占比（预测 / 目标） | 0.25 / 0.06 | **0.1331 / 0.1433** | ⚠️ 见下 |
| 单曲 SI-SDR vs 教师 | −6.53 dB | **−3.27 dB** | ⚠️ n=1，见 §4 |
| 推理 RTF（GPU） | 0.0132 | 0.0139 | 基本不变 |
| 学生人声电平 | −26.49 dBFS | −25.97 dBFS | 教师 −25.29，已对齐 |

**掩码过预测被修正了**（这是比 loss 更有意义的信号）。v1 预测掩码均值 0.25 而目标只有 0.06，
意味着模型系统性地"过度保留"——输出里混着大量原混音（当时"与混音相关度 0.73 >> 与教师 0.42"
就是这个现象）。v2 的预测均值 0.2275、>0.5 占比 0.1331 已经贴住目标的 0.1433。

## 4. 复核：单曲 SI-SDR 是骗人的（本轮最重要的方法学修正）

本轮训练脚本自己报的 "−6.53 → −3.27 dB，提升 3.26 dB" 听起来很漂亮，
但它是在**一首曲子**（`Le Youth - Chills` 的 60–100 s）上算的。n=1 不足以支撑任何结论。

于是写了 `scripts/13_ab_compare.py`：**同一批 8 首留出曲目、同一段 30 秒、同一份教师输出**，
把 v1 和 v2 两个 checkpoint 放在完全相同的条件下比。

判据说明：`mix~T` = SI-SDR(混音, 教师人声)。**人声本来就是混音的一部分，
所以这个值在正常段落必然是 0 dB 上下**；如果掉到 −10 dB 以下，说明这段音频根本没有人声，
教师输出的是噪声，任何针对它的 SI-SDR 都是没有意义的。

| 曲目 | mix~T | 教师人声 | v1 | v2 | 增益 | 可判读？ |
|---|---|---|---|---|---|---|
| Lane 8, Sultan + Shepard - Quiet Rush | −22.86 | −41.2 | −23.93 | −22.79 | +1.14 | ✗ 无人声 |
| Fred V - Really Happy Aliens | −10.76 | −26.8 | −9.09 | −8.58 | +0.50 | ✗ 无人声 |
| ÆON_MODE, ANY - Fireflies | −5.82 | −15.2 | −1.21 | −0.36 | **+0.85** | ✓ |
| Jerro, Le Youth, Lizzy Land - Forever x Lost | −3.23 | −21.4 | +0.47 | **+3.74** | **+3.27** | ✓ |
| ÆON_MODE - RUN | −17.07 | −23.6 | −10.60 | −10.80 | −0.20 | ✗ 无人声 |
| Robyn, Jamie xx - Dopamine (Jamie xx Rmx) | −11.30 | −21.7 | −1.68 | −2.88 | −1.20 | ✗ 无人声 |
| Tris - still holding on | −1.33 | −15.5 | +5.18 | **+5.77** | +0.59 | ✓ |
| Synergy - Mirage | −9.50 | −22.7 | −5.07 | −8.00 | −2.93 | ✗ 无人声 |

| 统计口径 | n | v1 中位 | v2 中位 | 中位增益 | 均值增益 | v2 更好 |
|---|---|---|---|---|---|---|
| 全部片段 | 8 | −3.38 dB | −5.44 dB | +0.55 | +0.25 | 5/8 |
| **含有效人声** | **3** | **+0.47 dB** | **+3.74 dB** | **+0.85** | **+1.57** | **3/3** |

**读法**：只看中位数会得出"v2 更差"的错误结论（−3.38 → −5.44），
因为 v1 的中位数恰好由两首退化的曲子撑着。真正可比的是逐曲增益：**5/8 变好**；
把不可判读的片段剔除后，**3/3 全部变好、中位 +0.85 dB、均值 +1.57 dB**。

### 这套协议的复现性（顺带验证了门控的必要性）

同一协议跑了两遍，逐曲对比：

| 曲目 | 第一次 | 第二次 | 偏差 |
|---|---|---|---|
| Fireflies | −0.36 | −0.36 | 0.00 |
| Jerro - Forever x Lost | +3.72 | +3.74 | 0.02 |
| Tris - still holding on | +5.77 | +5.77 | 0.00 |
| 其余四首 | — | — | ≤ 0.25 |
| **Lane 8 - Quiet Rush** | **−28.90** | **−22.79** | **6.11** |

有意义的曲目一致到 **0.02 dB**；只有 Lane 8 那首漂了 6 dB ——
而它正是教师人声只有 **−41.2 dBFS** 的那一首。
**SI-SDR 在近乎静音的片段上是数值不稳定的**：参考信号的幅度本身就接近数值噪声，
所以这个指标在那里没有意义。这也解释了为什么它必须被门控剔除，
而不只是"略有噪声"。

**这次 A/B 的净收益是纠错**：单曲的 +3.26 dB 是运气（那首恰好是增益最大的之一），
真实提升量级是 **0.6–1.6 dB**，方向可靠但幅度远小于第一印象。

## 5. 新发现：训练数据的瓶颈从"量"变成了"质"

8 个 50% 位置的窗口中，**5 个的教师人声只有 −21 ~ −43 dBFS，即根本没有有效人声**。

| 判据 | 观测 |
|---|---|
| 教师人声电平 | −43.5 / −26.8 / −15.2 / −21.4 / −23.6 / −21.7 / −15.5 / −22.7 dBFS |
| 混音电平 | 约 −10 dBFS |
| → 人声相对混音 | 普遍低 **5 ~ 33 dB** |

这直接影响训练：`11_smoke_train.py` 每首曲子按 **15%–75% 的均匀随机位置**截一段 30 秒。
如果 House/EDM 曲目里真正有人声的时间占比很低，那么：

- 大量算力花在"教模型在无人声处输出静音"上 —— 而模型本来就会这个；
- 更糟的是，这会给"掩码 → 0"这个吸引子持续供给梯度，
  而这正是报告 05 里那个静音塌陷陷阱的成因。上次是靠改损失函数压住的，
  现在看**数据层面的同源风险还没解决**。

**结论：下一步必须先做窗口筛选，而不是继续堆数据量或步数。**
可行做法（按成本排序）：
1. 用教师人声/伴奏能量比给窗口打分，只保留人声占比高于阈值的窗口（教师已经跑过，几乎零额外成本）；
2. 每首曲子取多个窗口而不是一个，按分数保留 top-k；
3. 对纯器乐曲目直接剔除（DJ 库里 drum & bass / techno 段落居多）。

## 6. 本轮顺带修的工程问题

1. **验证集每次都在变**（真 bug）。`evaluate()` 复用了训练用的随机数发生器，
   所以每次验证抽的 crop 都不同，val 曲线在 1.13–1.40 之间抖动 ±0.15 ——
   被记为"最佳"的 1.124（第 6200 步）用同一份权重重算是 1.296，差 0.17 全是采样噪声。
   → 改为每次固定 seed，验证 batch 数从 4 提到 8（可 `--val-batches`）。
   **在此之前，"best-val 早停"和细粒度模型选择都是不可信的。**

   **修完之后的复测**（`scripts/11_smoke_train.py --skip-train --init-from`，
   复用同一份缓存，32 个 batch = 512 个 crop）：

   | 测法 | 样本量 | v2 权重得分 |
   |---|---|---|
   | 训练中记录（复用训练发生器，`best`） | 64 crop | 1.124 |
   | 同一权重、seed 0 重算 | 64 crop | 1.296 |
   | **固定 seed + 512 crop（可信值）** | **512 crop** | **1.2049** |

   三者的差异全部来自验证样本，不是模型。**以 1.205 为准**；
   同口径下未训练网络的起点是 2.475。同一权重重测得出的掩码健康度与 SI-SDR
   与训练时完全一致（0.2275 / 0.2458 / −3.27 dB），说明推理路径是确定性的。
2. **缓存不可续跑**。`build_cache` 一旦发现有缓存文件就整体跳过，
   扩数据时必须 `--rebuild` 从头重算。→ 改为可续跑（利用 `find_tracks` 的洗牌前缀稳定性）。
3. **新增 `--time-budget-s` / `--ckpt-every` / `--use-best` / `--init-from` / `--cache-dir`**：
   按墙钟时间收工、定期存盘、用最佳权重做听感测试、从已有权重热启动、
   复用别的 run 的伪标签缓存。半小时这种碎片时间是一等公民，
   不该为了"跑够步数"浪费，也不该每次重付教师成本。

## 7. 下一步（按优先级）

1. **窗口筛选**（§5）：先给全库窗口打人声占比分，再决定训练集。这是当前最高杠杆。
2. **验证集扩到 20+ 首，并固定**（已在 v2 达到 22 首，但需要 §6.1 的固定 seed 才可信）。
   当前 3 首可判读样本太少，连"v1 vs v2"都只能给出 ±0.5 dB 量级的分辨率。
3. **因果消融**（项目最大未知数）：严格因果 vs 200 ms 前瞻 vs 非因果。
   前置条件仍未满足 —— 需要先有可用的学生模型。当前学生离教师还差 ~6–10 dB
   （含有效人声片段中位 +3.72 dB vs 教师），远未到教师水平，
   此时测"因果损失了多少"测的是噪声。
4. 全库外推（~25 h 音频）：伪标签 ~1 h + 50 epoch ~3 h ≈ **4 小时**，
   加上 §7.1 的筛选会更便宜（保留窗口更少）。
