# 冒烟训练验证报告

> 目标：用最少的算力确认**三件事** —— 数据链路通不通、教师伪标签跑不跑得动、以及**这个因果 U-Net 到底学不学得会**。
> 最后一条是整个方案唯一没有答案的问题，本轮第一次有了答案。

**结论：链路通、结构学得会，但抓到一个会致命的训练陷阱，已修复；质量距可用还很远，瓶颈是数据不是步数。**

---

## 1. 三阶段实测吞吐

| 阶段 | 规模 | 实测吞吐 | 耗时 |
|---|---|---|---|
| ① 教师伪标签（HTDemucs） | 30 首 × 30 s = 900 音频秒 | **17.0 音频秒/秒**（含解码 + STFT） | 53.0 s |
| ② 学生训练 | 6000 步 × batch 16 × 1.486 s | **411.5 音频秒/秒** | 346.7 s |
| ③ 推理（40 s 留出片段） | 6891 帧 | **RTF 0.013**（比实时快 77 倍） | 0.53 s |

### ⚠️ 合成基准高估了 3 倍

`10_cpu_vs_gpu.py` 用合成张量测出教师 54 音频秒/秒，**实测只有 17**。差距来自 `apply_model` 的分段重叠推理、mp3 解码、输入归一化。**以后做容量规划要用这一轮的实测值，不要用合成值。**

另外 `spec` 列（STFT + 掩码压缩）普遍只要 0.06–0.13 s / 30 s，与"前端 0 MAC"的设计一致。

## 2. 抓到的致命 bug：模型学会了"输出静音"

### 2.1 症状

第一版跑完 600 步，指标看着很健康：

```
val L1: 1.95895 -> 0.32660  (LEARNED, -1.6324)
```

但导出的音频 SI-SDR 是 **−50.3 dB** —— 等于没输出。

**loss 在降，音频是死的。这两件事不可能同时成立，说明指标本身在骗人。**

### 2.2 诊断（`12_smoke_diag.py`）

先确认老师→掩码这一段是**健康**的：

| 检查项 | 结果 |
|---|---|
| 人声/混音能量比 | −4.4 dB（合理） |
| band 掩码均值 | 0.2314 / 0.2423 |
| oracle 掩码过 128 频带 → iSTFT | **SI-SDR 9.74–12.80 dB** ✓ |

再查学生，问题一目了然：

| 量 | 值 |
|---|---|
| 网络输出 ch0:2 | **恒等于 −1.0000，std = 0** |
| 映射后掩码 ch0:2 | 全部 0.0000 |
| 学生人声电平 | **−135.18 dBFS**（静音） |
| 训练好的网络 L1 | **0.3632** |
| 常数「全部静音」的 L1 | **0.3632** ← 一模一样 |
| 常数「掩码 = 0.5」的 L1 | 0.8468 |
| 目标掩码中位数 p50 | **0.04** |

**训练好的网络，和一个"永远输出静音"的常数，在验证集上得分完全相同。**

### 2.3 根本原因

两个因素叠加成陷阱：

1. **目标掩码极度偏斜。** 原来用 Wiener 掩码，经 `[0,1]` 截断后 90% 以上的值都是 0 —— 截断把质量堆在 1.0 上，其余全部压到接近 0。
2. **L1 损失的最优常数是条件"中位数"**，不是均值。既然中位数就是 0，`掩码 ≡ 0` 就是一个很强的吸引子。600 步足够滑进去。

于是 loss 的下降**全部来自"变安静"**，没有一分来自"学会分离"。这是分离任务里最经典的塌陷模式，也是无真值评测里最容易自欺的地方。

### 2.4 修法（三处）

**① 换目标掩码。** Wiener → 标准软掩码：

```
m = |V| / (|V| + |A|)
```

天然落在 `[0,1]`，不需要截断，动态范围也更健康。缓存里目标掩码均值范围从原来的 0.003–0.33 变成 **0.0081–0.4099**，近空目标从 3 个降到 1 个。

**② 换损失。** 对掩码做 L1 → 对**重建幅度做对数 L1**：

```
L = L1(log(x · m̂_voc + ε), log(x · m_target + ε))
  + L1(log(x · m̂_acc + ε), log(x · m_target_acc + ε))
```

对数让每个时频点权重相同，与能量大小无关。目标有人声而你输出静音，要付满整个动态范围（≈10）。**静音不再是便宜解。**

这个改法**完全不触碰推理路径**——掩码还是掩码，tanh 还是 tanh，FPGA 规格里的 0.53 M 参数 / 517 KB / RTF 0.056 一行都不用改。只换训练目标。

**③ 加塌陷检测。** 报告里直接盯预测掩码的 `std`，不只看 loss。`std < 0.02` 就报警。

### 2.5 验证

| 指标 | 修复前 | 修复后 |
|---|---|---|
| 预测掩码 std | **0.0000** | **0.2270** |
| 学生人声电平 | −135.18 dBFS | −26.49 dBFS |
| 与老师人声波形相关度 | — | **+0.4172** |
| SI-SDR vs 老师人声 | −50.3 dB | −6.53 dB |
| 与混音相关度 | — | 0.7340 |

掩码不再恒定，输出电平落在老师人声附近（−26.5 vs −25.3 dBFS），波形与老师真实相关。**模型第一次真正产出了音频。**

## 3. 结构确实学得动

6000 步的训练曲线：

```
step       train         val
   1     2.19355     2.72030
1000     0.89465     1.63484
3000     0.77478     1.65772
5000     0.60838     1.63408
6000     0.62078     1.68162
```

- 训练损失 **2.19 → 0.62**（降 3.5 倍）
- 验证损失 **3.08 → 1.84**（降 1.7 倍）
- 掩码预测均值 0.2504 vs 目标 0.0611 —— **仍在过度预测**，说明没学透

`voc + acc` 精确重建混音（最大误差 5.96e-08），互补掩码结构在数值上是成立的。

**三条此前只有假设、现在有证据的事：**
1. 因果 U-Net 这个结构**能**从 128 频带幅度谱里学到人声掩码；
2. 128 频带的固定滤波器组前端**无损**（oracle 过这段仍有 9.7–12.8 dB）；
3. STFT → 滤波组 → U-Net → 掩码上采样 → iSTFT 全链路可微、可训练。

## 4. 但质量远不可用 —— 瓶颈是数据，不是步数

| 训练步数 | 人声 RMS | SI-SDR vs 老师 | 与老师相关 | 与混音相关 |
|---|---|---|---|---|
| 1500 | −23.22 dBFS | −8.24 dB | 0.3520 | 0.8232 |
| 6000 | −26.49 dBFS | −6.53 dB | 0.4172 | 0.7340 |
| **可达上限**（128 频带 oracle） | −25.29 dBFS | **+9.87 dB** | — | — |

### 两个关键读数

**① 4 倍步数只换来 1.7 dB。** 从 1500 步到 6000 步，验证损失几乎完全没动（1.835 → 1.841）。

**② 输出里还混着大量原混音。** 与混音的相关度 0.734 远高于与老师的 0.417 —— 说明模型还没真正"挑出人声"，更像是给混音打了个折。

原因很直白：

> 训练集只有 **27 首 × 30 秒 = 13.5 分钟**唯一音频，却喂了 **142663 音频秒 = 39.6 小时**的训练量 —— **重复了 176 倍**。

这不是训练不足，是**数据不足导致的过拟合**。继续加步数没有意义。

---

## 5. 扩到全库需要多少算力

| 项 | 本轮冒烟 | 全库真训练 |
|---|---|---|
| 唯一音频 | 13.5 分钟 | **~25 小时**（320 首整曲） |
| 教师伪标签 | 53 s | **~1 小时**（按实测 28 音频秒/秒 + 解码） |
| 一个 epoch | — | 3.6 分钟 |
| 训练 50 epoch | — | **~3 小时** |
| 验证集 | 3 首（噪声极大） | 建议 **20 首** |
| **合计** | 3 分钟 | **~4 小时** |

**一轮完整训练的代价只有约 4 小时**，完全可承受。伪标签缓存机制意味着之后所有消融实验都只付训练那 3 小时。

---

## 6. 下一步建议（按优先级）

1. **扩数据到全库**：320 首、整曲使用，每首多切几段并拉开切段位置（本轮每首只取 30 s 随机 15%–75% 位置，是数据量不足的主因）。
2. **验证集扩到 20 首**。现在 3 首让 val 曲线噪声大到看不出趋势，这是刚才误判"还在学"的直接原因。
3. **调损失配比**。模型仍过度预测掩码（0.25 vs 0.06），建议加稀疏惩罚或对静音区加权。
4. **补掩码时间平滑**（规格 §4 第 3 条的音乐噪声问题）——本轮还没测，但它是连续听感的第一号杀手。
5. **最后才做因果性消融**。这仍是方案最大的未知数，但要等模型真正学得动了才有意义 —— 现在测出来的差值是噪声。
