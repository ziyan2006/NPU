## 1. 目标

### 1.1 产品形态

```
out = mix_delay − g · vocal_est
```

- 模型**常开**，始终在算人声估计 `vocal_est`；
- 按键只切换标量 `g`（1 → 0），用 **30 ms 斜坡**防止爆音；
- 因此**按键本身零额外算力**，也不需要重跑模型；
- 分离目标只有 2 stem：人声 / 伴奏（伴奏 = 所有非人声 stem 之和）；
- **反相消声（`(L−R)/2`）已排除**：只剩 5.8% 能量、整体掉 12.34 dB、与真伴奏相关度 −0.008
  → 空间线索不足，**必须按音色判断，这正是 NPU 的价值**。

### 1.2 三个延迟口径（绝不能混）

| 口径 | 数值 | 用户感知 |
|---|---|---|
| **通路延迟**（输入端到扬声器） | **133.5 ms**（恒定，chunk = 16 帧） | 纯播放，错位恒定 → 无感 |
| **按键响应**（按下到听感变化） | **≈30 ms** | 这是用户唯一真正感知的延迟 |
| **冷启动**（上电到首帧出声） | **≈110 ms** | 一次性 |

> 端到端延迟公式：`n_fft/sr + (3 + chunk) · hop/sr`。
> **chunk 必须是 8 的倍数**；chunk 越大 DDR 带宽越宽松，但激活线性增长。推荐 **16**。
> ⚠️ DJ 场景下 133 ms 固定错位会打乱节拍对齐 —— 这是产品层面需要权衡的点。

### 1.3 为什么必须要 NPU

免费的反相消声会连整首器乐一起删掉（相位/空间线索不足以分离真实混音）。
统计分离必须按**音色**判断，即需要学到的时频掩码 → 需要 NPU。

### 1.4 交付边界

- ✅ 算法定义、规格、量化方案、延迟账、训练权重、评测结论：**已定稿**
- ✅ INT8/INT12 量化方案与精度损失：**已实测**
- ✅ NPU ISA、描述符、tile 编译器、bank/周期模型：**已有可执行提案**
- 🚧 PL 侧 RTL：**P4 原型进行中**，已有 Command Processor、Descriptor Cache、DMA AGU
- 🔜 AXI DMA engine、MAC/Vector 数据通路、SoC 集成和端到端上板实测：**未完成**

## 2. 算法规格（已冻结）

### 2.1 网络结构

因果（causal）频域 U-Net：

| 环节 | 配置 |
|---|---|
| STFT | `n_fft=1024 / hop=256` @ 44.1 kHz 立体声 → 513 bin |
| 输入压缩 | **固定滤波器组** 513 → **128 频带**（线性映射，**0 MAC**） |
| 编码器 | 2 → 32 → 64 → 96 → 128 通道，stride `(1,2,2,2)` |
| 瓶颈 | stride `(1,3)` |
| 解码器 | 镜像 + skip connection |
| 输出 | 复掩码 → 插值 128 → 513 频带（**0 MAC**）→ iSTFT |
| 因果性 | 无任何前瞻；实测「扰动末帧 → 176 帧仅 1 帧变化」 |
| 管线无损性 | 掩码 ≡ 1 时，输出 vs 混音 **SI-SDR = 138.81 dB** |

> ⚠️ **已知缺陷（不影响出结论，但要记住）**：128 个频带是**对数**划分，而 STFT 频点间距是 43 Hz
> → **49/128 个频带整列为 0，实际只有 79 个有效带**。
> 但**不是质量瓶颈**：均匀 128 带天花板更低（6.74 dB），对数 128 带天花板 12.06 dB，
> 而学生实测离天花板还差 ~9 dB。**瓶颈在损失函数，不在表征。**

### 2.2 算力与存储预算

| 项 | 值 |
|---|---|
| 参数量 | **0.5297 M** |
| INT8 权重 | **517 KB** |
| 计算量 | **1.226 GMAC / 音频秒** |
| 激活（融合流式） | 276 KB（8 bit）/ **414 KB（12 bit，BRAM 66%）** / 552 KB（16 bit） |
| 推理 RTF | **0.007 – 0.014** |
| PL 可用算力 | ~22 GMAC/s（模型只要 1.2） |

> **核心判断 ①：瓶颈是 BRAM，不是 DSP。**
> **核心判断 ②：频带数决定激活规模 → 比通道宽度更关键。**
> **核心判断 ③：参数多 ≠ 算力贵**（HDemucs 83.6 M 参数只要 9.5 GMAC/s）→ **用 MAC/音频秒 判可行性。**
> 反面教材：开源强基线全部倒在**因果性**上（HTDemucs 前瞻 3900 ms / HDemucs 20000 ms / UMX 无界）。

### 2.3 量化方案

**INT8 权重（per-channel）× INT12 激活 × uint8 掩码，INT32 累加。**

| 激活位宽 | 重建质量 | 激活体积 | 结论 |
|---|---|---|---|
| 8 bit | **10.4 dB** | 276 KB | ❌ 可闻 |
| **12 bit** | **28.7 dB**（v4_best 复核 29.58 / probeC 复核 **29.74**） | **414 KB** | ✅ **采用**（不可闻，BRAM 66%） |
| 16 bit | ~36 dB | 552 KB | ❌ 装不下 |

- **代价全在激活位宽**：掩码 8 bit 仍有 +58 dB、权重 INT8 有 +34 dB；
- **DSP48E1 是 18×25 位乘法器 → INT12 激活零额外乘法器**，代价只是多 138 KB BRAM；
- `a8_noin ≈ a8` → **输入量化几乎无损**；
- 累加器位宽 26 bit；
- **不做 QAT**（后训练量化已达标）。

### 2.4 出货配置（当前）

| 项 | 值 |
|---|---|
| 权重 | **`models/student_k3s_model.pt`**（K=3 数据形状、900 s 等预算训练） |
| 推理期后处理 | **`<250 Hz` 人声掩码强制为 0**（`separate(..., lf_kill_band=250)`） |
| 量化 | INT8 per-channel 权重 × INT12 激活 |
| 低频保护收益 | 人声 **+0.68~0.78 dB** / 伴奏 **+0.37~0.55 dB**，**12/12 双赢** |
| 关键性质 | **零硬件成本**，且**与权重无关**（在 v4 / probeC / k3s 三个权重上全部成立） |
| 边界 | `<350 Hz` 会导致人声崩塌（1.913）→ **不要越界** |

## 4. 当前进度

### 4.1 训练史（每轮只改一个自变量）

| 轮次 | 数据 | 步数 | train log-L1 | val log-L1 | A/B 结论 |
|---|---|---|---|---|---|
| v1 | 30 首 × 30 s | 6 000 | 0.712 | 1.694 | 基线 |
| v2 | 220 首 × 30 s | 15 813 | 0.877 | 1.231 | vs v1：中位 **+0.95 dB**，8/8 全胜 |
| v3 | 220 首 + 筛选窗 | 17 943 | 0.742 | 1.210 | — |
| v4 | 274 首 × 60 s | 88 948 | 0.71 | 1.0318（最佳 0.9619 @1500 后一路退化） | vs v3：**−0.06 dB（11/24）→ 打平略负** |
| probeB | v4 + **能量加权相对损失** | best @750 | — | 0.9720 | ❌ **−2.18 dB**（0/14） |
| probeC | v4 + **掩码加权损失** `1+λ·t_v` | best @1850 | — | 0.9589 | ✅ **+0.15 dB**（13/19）—— 首个正向 |
| k3w | K=3，3 h | 93 994 | — | **从未改善一步** | ⚠️ 无产出（`--use-best` 把 init 写回） |
| k3s | K=3，等预算 900 s | 6 533 | — | 0.98873 → 0.97710（**更差**） | ✅ 留出集 **+0.21 dB（13/19）** |

> ⚠️ **不同版本的 val log-L1 不可相减**（验证集随数据切分变化）。
> 只有 **v3 ↔ v4** 在同一固定标尺上可比。所有质量结论都来自同批留出集 A/B。
> ⚠️ `--val-batches` 会改变标尺：同权重同缓存，`--val-batches 16` 得 0.96775、默认得 0.98873。

### 4.2 已确认的正向结果 ✅

1. **低频掩码保护 `<250 Hz`** —— 人声 +0.68~0.78 / 伴奏 +0.37~0.55 dB，12/12 双赢，**零硬件成本、与权重无关**。
2. **掩码加权损失 `logl1+wmask`（λ=2）** —— 三个取窗位置符号全为正，合并 +0.15 dB（13/19），
   是**第一个正向的损失修法**（probeB 的能量加权是负的）。
3. **K=3 数据形状** —— 留出集 A/B **+0.21~0.32 dB**，**5/5 位置 × 检查点全为正**，
   角色对调对照排除了 slot 偏置。
4. **INT12 激活量化** —— 29.74 dB，不可闻，BRAM 66%。
5. **因果性链路** —— 单帧扰动只影响 1 帧；掩码=1 时管线 SI-SDR 138.81 dB（无损）。

### 4.3 已确认的负结果 ❌（不要重试）

1. **堆数据 / 堆步数**：v1 用 15 分钟数据就到 train 0.7122，v4 用 274 分钟、88 948 步还是 0.71。
   → **损失地板由模型/目标函数决定，不由数据决定。**
2. **数据增强**：全开跑满 900 s，最佳 0.9663，仍差于 v4 的 0.959。
3. **能量加权相对损失（probeB）**：−2.18 dB，只在无人声段变好（+5.12）→ 学成"干脆不动"。
4. **加频带数**：天花板从 128 → 256 带只值 +1~3.8 dB，补不上 9 dB 的差距。
5. **"只加长调度"**：已有**四次**负证据。
6. **反相消声**：整首掉 12.34 dB，已排除。

### 4.4 ★ 两个标尺的分歧（本轮最重要的方法论结论）

> **K=3 让 val log-L1 变差、但让留出集 SI-SDR 变好 —— 两个标尺第一次符号相反。**

原因清晰：

- **val** 只看**窗口筛选选中的那一个** 60 s 窗内的 1.5 s 片段；
- **产品**播的是**整曲任意位置**的 30 s。

K=3 买到的正是**位置多样性**（rank1/rank2 窗口的 `vocal_db` 与 rank0 **完全相同**，
落差 +0.00 dB → 是多样性，不是稀释），所以产品标尺变好、val 变差。

**⇒ 硬规则：`val log-L1` 不再用于选择模型，以留出集 A/B 为准（或两者同时报）。**

### 4.5 损失诊断（说明为什么瓶颈在目标函数）

`18_loss_attribution.py` 的归因：

- 近静音格子占 **39.6%** 的 bin，却只贡献 **0.5%** 的损失；
- 模型对"目标掩码 = 0"的格子误差 **0.000**；
- **86.8% 的人声损失落在 `0 < mask ≤ 0.5`** —— 即"该压但压不准量"；
- 静音预测器 7.11 vs 模型 0.95 → 模型**远离塌陷**；
- **根因是目标与指标错配**：log-L1 按**格子计数**、SI-SDR 按**能量加权**
  → 这解释了"train 降、SI-SDR 不涨"。

## 5. 关键陷阱与硬规则（**不要重犯**）

1. **掩码塌陷**：loss 从 1.96 掉到 0.33 但 SI-SDR −50 dB。
   判据：**训练 L1 == 常数静音 L1（0.3632）**。
   根因：L1 的最优常数是条件中位数，而目标掩码中位数为 0 → `掩码≡0` 是强吸引子。
   修法：软掩码 `|V|/(|V|+|A|)` / 对数 L1，**必须盯预测掩码的 std**；crop 帧数取 8 的倍数。
2. **无谓静音窗口**：随机截窗会教模型"无人声处输出静音"。
   → 必须用**窗口筛选**（`--scan-s 180 --n-cand 5 --min-vocal-db -40`）；
   筛选后 80% 片段的人声/混音 > −12 dB（中位 −8.4 dB）。
3. **`--val-batches` 会改 val 标尺**（漏传一次差 0.021）→ **所有 val 数字必须同标尺**。
4. **缓存按 `--tag` 命名**：换 tag 会落到空目录并**重跑筛选（≈1 h）**。
   复用缓存必须显式传 `--cache-dir`，并核对 `_meta.json`（`seg/scan_s/n_cand/min_vocal_db`）。
5. **★ 换缓存 = 换标签**：HTDemucs 教师伪标签在 CUDA 上**不可复现** ——
   同代码同音频两次运行，`mix` 逐位相同、但 `mask` 平均差 **0.006–0.017**（3–11% 的 bin >0.05）。
   → 跨缓存比 val **必须先用同一份权重在两缓存各算一次 init val** 量出偏移（实测 0.0089）。
6. **续跑必须按文件名、不能按文件数**：旧逻辑一旦上一轮筛掉过曲目就会把尾巴重标一遍
   → **静默重复曲目**（`v4_cache` 274 文件其实只有 272 首）。**已修**（见报告 §19）。
7. **★ 模型间比较必须用"逐曲差额的中位"**，不能用"两个中位数相减" ——
   同一份数据上，前者 **+0.22**、后者 **−0.13**，**符号相反**。
8. **A/B 运行间噪声底 ≈ 0.2 dB**（近静音参考放大浮点非确定性，最多 1.5 dB）→
   低方差协议 = `--frac 0.25/0.5/0.75` **三跑逐曲平均**。**< 0.2 dB 不能靠单次运行宣布。**
9. **评价约定**：
   - `n=1` 不可下结论；
   - 必须看**逐曲增量**（v1 −3.38 / v2 −5.44 看着更差，实际 5/8 变好）；
   - **人声存在性门控**：`SI-SDR(mix, teacher_vocal) < −10 dB` → 这首没有人声，教师输出是噪声，剔除；
   - **SI-SDR 在近静音上不稳**（有效曲重跑一致 0.02 dB，−41 dBFS 那首漂 6.11 dB）；
   - 留出集必须**显式 carve**（`--holdout N`）并按**文件名**去重（319 文件 → 298 首）。

## 7. 快速开始

### 7.1 环境

```bash
PY=python
$PY -c "import torch,demucs,librosa; print(torch.__version__, torch.cuda.is_available())"
```

若需重建环境：Python 3.13 → `torch==2.14.0+cu126`、`torchaudio==2.11.0+cu126`、
`demucs==4.1.0`、`librosa`、`soundfile`、`openunmix`、`museval`。

### 7.2 加载出货权重推理

```python
# 模型定义在 scripts/09_target_model.py，低频保护 + 分离函数在 scripts/11_smoke_train.py：
#   separate(net, mix, Wa, Gs, device, lf_kill_band=250)   # ★ <250 Hz 掩码置 0
#   lf_kill_band_for(250.0) -> 频带索引
# 完整调用示例见 scripts/20_mask_postproc.py，权重用 models/student_k3s_model.pt
```

### 7.3 复现 A/B（低方差三位置协议）

```bash
PY=python
$PY scripts/13_ab_compare.py \
    --a models/student_probeC_best.pt \
    --b models/student_k3s_model.pt \
    --frac 0.25      # 再跑 0.50 / 0.75，然后对逐曲差额取中位
```

> - 留出集由 `results/v2_report.json` 定义（`--names-from` 的默认值）——**这个文件必须保留，换掉会改标尺**。
> - 需要训练缓存（**本仓库不含**，24 GB 太大）。
>   重建：`$PY scripts/11_smoke_train.py --tag my_run --crops-per-track 3 ...`（教师筛选 ≈1 h）。
> - `--frac` 默认 0.5（历史位置）；单次结果在近静音曲目上可漂到 1.5 dB，所以低方差协议是**三跑平均**。

### 7.4 试听出货效果

公开仓库不分发商业歌曲试听片段。可使用自有或获授权音频，通过
`scripts/21_render_demo.py` 生成含 `<250 Hz` 保护和无保护的对照结果。

## 8. 待办与未决问题 ⚠️

### 8.1 唯一的出货前必做项

> **K=3 的 +0.25 dB 必须先复现。**

原因是**"更多数据"和"更多步数"这次一起变了**：

| | probeC 最佳点 | k3s |
|---|---|---|
| 步数 | 1 850 | **6 533（3.5×）** |
| 数据形状 | K=1 | K=3 |

而"只加长调度"已有四次负证据 → **不能把增益归因给 K=3**。
需要一次**步数对齐**（或换种子）的运行把两者分离。

**幅度与 A/B 噪声底（~0.2 dB）同量级 → 必须复现才敢出货。**

### 8.2 其他

- [ ] `v4_cache` 的重复曲目**未回溯修**（会改 val 切分、作废全部历史 val 数字）→ 新缓存已修，旧缓存保留现状。
- [ ] 教师伪标签的 CUDA 非确定性可尝试固定：
      `CUBLAS_WORKSPACE_CONFIG=:4096:8` + `torch.use_deterministic_algorithms(True)`（待验证）。
- [ ] **"音乐噪声"是第一号杀手**，离线指标看不出 → 延迟预算应花在**掩码时间平滑 / 轻微前视**上，
      **不要靠加大模型**。
- [ ] PL 侧 RTL/HLS、板上端到端实测（未开始）。
- [ ] 少量**真值（MUSDB18）终验**：蒸馏方案的风险是继承教师错误。

### 8.3 最大未知数

**因果 vs 非因果的 SDR 损失**（估计 0.5–1.5 dB）—— 这是本方案的根本代价，
需要用真值做一次对照才能量化。
