# XC7Z020 人声消除专用加速器架构 v0.1（历史基线）

> 状态说明：本文记录早期固定模型方案和已有性能测算。项目已转向轻量通用 CNN NPU；通用设计以 `00_spec_index.md` 和 `10_system_requirements.md` 为准。本文中的“冻结”只对历史专用方案成立。

## 冻结边界

硬件按较大的 MIR-1K 候选模型设计，后续算法训练只允许更新权重和量化尺度：

| 项目 | 冻结值 |
|---|---:|
| 输入 | 双声道、44.1 kHz PCM |
| STFT | 1024 点，hop 256 |
| 网络输入 | `2 × 128 × 16`，幅度谱，16 帧一块 |
| U-Net 通道 | 32 / 64 / 96 / 128 |
| 瓶颈 | 1 个 `1×3` 卷积 + 2 个 `3×3` 残差块 |
| 网络输出 | `4 × 128 × 16` 掩码；产品只消费前两个人声通道 |
| 低频保护 | `<250 Hz` 的前 44 个频带强制人声掩码为 0 |
| 量化 | INT8 权重、INT12 激活、INT32 偏置/累加、UINT8 掩码 |
| 按键公式 | `out = delayed_mix - g × vocals`，`g` 在约 30 ms 内渐变 |

当前候选有 824,900 个参数，CNN 为 123,338,752 MAC/块，即约 1.328 GMAC/音频秒。按保守的 22 GMAC/s 持续吞吐估算，单块计算约 5.61 ms；16 帧块的音频时长为 92.88 ms，计算余量约 16.5 倍。

## 系统数据流

```text
I2S/DDR PCM
    │
    ▼
双声道环形缓冲 ──► 1024 FFT ──► 幅度 ──► 513→128 固定频带
                                              │
                                              ▼
                                  INT12 因果 U-Net NPU
                                              │
                                              ▼
                                  tanh/UINT8 人声掩码
                                              │
                                              ▼
128→513 插值 ──► 复频谱乘法 ──► iFFT/OLA ──► 人声估计
                                              │
延迟对齐的原混音 ──────────────────────────────┼──► mix - g·vocals
```

第一阶段建议把 CNN 加速器做成独立 AXI4-Stream 核；FFT、iFFT 和 overlap-add 使用现成 IP 或单独 HLS 核。这样最先验证计算量最大的部分，同时保持前后端可独立替换。

## CNN 执行结构

使用一组可复用的卷积 PE 阵列顺序执行 11 个卷积层，不为每层复制完整硬件：

1. DMA 从 DDR 预取下一层的 INT8 权重到片上 weight tile；
2. 当前层在 INT12 激活上运行，INT32 累加；
3. 加偏置、逐输出通道 requant、LeakyReLU；
4. 编码器输出写入 skip buffer；
5. 解码器用地址重复实现 nearest upsample，以双输入流代替物化 concat；
6. 两个瓶颈块在相同尺度下完成残差加法；
7. 最后一层走 tanh LUT，并转换为 UINT8 掩码。

卷积核只需支持 `1×1`、`1×3`、`3×3`，stride 只需 1 或 2。时间轴只左填充，频率轴对称填充，禁止读取未来帧。

首版 PE 阵列采用 `Pout=8 × Pin=8`，共 64 条 INT8×INT12 MAC lane。考虑首尾层通道不足8造成的空 lane，完整调度为 1,986,560 周期：200 MHz 下理想值 9.93 ms，按50%控制/访存效率估算约19.87 ms，仍小于46 ms的首阶段门槛。CNN 只占64个 DSP48E1，剩余 DSP 可留给 FFT、复数乘法和系统集成。若综合后的 BRAM/布线宽裕，再把 `Pout` 提到16；不把220个 DSP一开始全部铺满。

## 存储方案

- 权重 blob 约 806 KB，大于 630 KB BRAM，固定存 DDR；每个 16 帧块完整读取一次约 8.9 MB/s，远低于保守 1.2 GB/s DDR 带宽。
- 激活采用 INT12。解码阶段不能物化完整 concat；应从 upsample buffer 与 skip buffer 双流取数。
- BRAM 首版预算：激活/skip/FIFO 不超过 460 KB，weight tile 96 KB，FFT/控制预留至少 64 KB。综合若超限，优先缩小 weight tile，而不是降低激活到 INT8。
- DMA 必须 ping-pong；计算当前层时预取下一层，避免 DDR 抖动变成音频掉帧。

INT8 激活已实测只有约 8.9 dB 的量化一致性，不允许为了省 BRAM擅自改成 INT8。INT12 实测约 25.6 dB，且 `8×12` 乘法落在 DSP48E1 原生乘法器宽度内。

## 延迟与流控

- 16 帧必须整块接受，帧数必须是 8 的倍数；
- 块音频时长 92.88 ms；网络必须在该期限内完成；
- 端到端固定延迟预计约 133.5 ms，按键增益位于输出端，因此按键听感响应仍由 30 ms 斜坡决定；
- AXI Stream 全链路传播 back-pressure，但音频入口必须有能覆盖最坏 DMA 抖动的异步 FIFO；
- 记录 `deadline_miss` 和 FIFO 高水位，任何 deadline miss 都视为产品错误。

## 第一阶段验收门槛

1. HLS/RTL C 仿真逐层对齐导出的 INT8/INT12 golden 数据；
2. 11 层完整执行时间小于 46 ms，先留 2 倍实时余量；
3. DSP 不超过 200，BRAM36 不超过 125，给系统集成保留余量；
4. 连续运行 30 分钟无 FIFO underrun/overrun；
5. 按键切换无爆音，低频保护索引固定为 44；
6. 后续权重包只要 `manifest.schema` 和图结构哈希一致即可热替换。

精确层尺寸、权重偏移、量化尺度和每层 MAC 以生成的 `hardware/generated/bott2_mir1k_v1/manifest.json` 为准。
