# NPU v1 系统需求基线

文档版本：`0.1-draft`

状态：P1 草案

## 1. 记号

- 优先级：`P0` 必须满足，`P1` 应支持，`P2` 可选。
- 状态：`C` 已确认，`P` 提案，`T` 待确认。
- 验证：`I` 检查，`A` 分析/模型，`S` 仿真，`Y` 综合/实现，`B` 板级测试。

“验证”列定义这条需求最终如何关闭，不代表只用一种手段。

## 2. 平台与系统边界

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| SYS-001 | P0 | C | NPU 必须可综合并部署于 `XC7Z020-1` PL。 | Y/B |
| SYS-002 | P0 | C | ARM PS 负责应用、内存分配、命令提交和异常处理；PL NPU 只执行预编译的静态张量程序。 | I/S/B |
| SYS-003 | P0 | P | NPU 的功能边界是量化张量输入到量化张量输出，不将 STFT/iSTFT、OLA 或音频编解码固化进 Tensor ISA。 | I/S |
| SYS-004 | P0 | C | v1 必须首先完整运行当前人声消除 CNN，并能更换权重而不重新综合 bitstream。 | S/B |
| SYS-005 | P0 | P | v1 必须再运行至少一个拓扑不同的小型 CNN，证明控制器、尺寸和地址未写死到人声模型。 | S/B |
| SYS-006 | P1 | P | 同一 bitstream 应允许连续提交不同模型的命令流；v1 不要求抢占正在执行的命令流。 | S/B |
| SYS-007 | P0 | T | 最终板卡型号、Zynq 封装、DDR 配置、速度等级和 Vivado 版本必须在 P1 冻结前记录。 | I |

## 3. 执行与功能

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| EXE-001 | P0 | C | 图在部署前编译为顺序命令流和描述符；运行时不解析 PyTorch、ONNX 或 JSON。 | I/S |
| EXE-002 | P0 | C | v1 只要求 batch=1、部署时静态 shape、有限循环边界和无数据依赖分支。 | I/S |
| EXE-003 | P0 | P | 每条命令通过描述符索引访问张量与算子参数，不在命令中硬编码某一层尺寸。 | I/S |
| EXE-004 | P0 | P | 命令处理器必须支持计算与 DMA 重叠，并在真实数据相关处提供同步语义。 | S/Y/B |
| EXE-005 | P0 | C | 非法 opcode、描述符越界、地址未对齐、DMA 响应错误和命令超时必须停止当前任务并报告错误，禁止静默产生输出。 | S/B |
| EXE-006 | P0 | P | 每次任务提交必须携带软件 tag，完成或失败时原样返回，便于驱动匹配。 | S/B |

## 4. 算子覆盖

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| OP-001 | P0 | C | 支持 INT8 权重的 2D 普通卷积，kernel 为 `1×1`、`1×3` 或 `3×3`，stride 每轴为 1 或 2。 | S/B |
| OP-002 | P0 | P | 支持 depthwise `1×1`/`3×3` 卷积；v1 不要求任意 group 数。 | S/B |
| OP-003 | P0 | C | 支持逐元素 ADD，用于残差连接；输入可在重定标后相加。 | S/B |
| OP-004 | P0 | C | 支持 NONE、ReLU、斜率可配置的 LeakyReLU，以及当前输出所需的定点 tanh/LUT 路径。 | S/B |
| OP-005 | P0 | C | 支持每轴 2× 最近邻上采样；必须允许只放大一个轴。 | S/B |
| OP-006 | P0 | P | concat 优先表示为多段张量视图并由读地址发生器消费，不强制复制成连续大张量。 | S/B |
| OP-007 | P1 | P | 支持逐元素 SUB、MUL、MIN/MAX 和 clamp。 | S/B |
| OP-008 | P1 | P | 支持 max/average pool，kernel 为 2 或 3，stride 为 1 或 2。 | S/B |
| OP-009 | P1 | P | 支持 GEMM，或由编译器可靠映射为 `1×1` 卷积。 | I/S |
| OP-010 | P0 | C | 不要求 Attention、Softmax、LayerNorm、LSTM/GRU、训练和浮点 Tensor 算子。 | I |

## 5. 数值格式

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| NUM-001 | P0 | C | 权重为 signed INT8、二补码、对称量化，支持逐输出通道 scale。 | S/B |
| NUM-002 | P0 | C | 激活运算至少支持 signed INT12 有效精度；INT8 不能作为当前人声模型的唯一激活格式。 | S/B |
| NUM-003 | P1 | P | 同一算术数据通路支持 INT8、INT12、INT16 激活，INT12 在 16-bit 容器中符号扩展。 | S/Y |
| NUM-004 | P0 | C | 乘加累加器和 bias 均为至少 signed INT32；当前模型静态分析的最大需求为 26 bit。 | A/S |
| NUM-005 | P0 | P | v1 Tensor 运算采用零点 0；非零 zero-point 由编译器在边界转换，或判定模型不受支持。 | I/S |
| NUM-006 | P0 | P | requant 使用整数 multiplier/shift，舍入为 round-to-nearest-even，溢出采用饱和，不允许硬件浮点 scale。 | S/B |
| NUM-007 | P0 | C | 相同命令、描述符和输入在仿真与板上必须得到 bit-exact 的整数 Tensor 输出。 | S/B |
| NUM-008 | P0 | P | 所有数值语义，包括负数右移、舍入、饱和和 LUT 边界，必须在 ISA 冻结前形成可执行 golden。 | S |

## 6. 存储与 DMA

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| MEM-001 | P0 | C | 完整权重和大张量驻留 DDR；片上 BRAM 用作显式管理的 tile、FIFO 和描述符缓存。 | I/Y/B |
| MEM-002 | P0 | P | 激活默认物理容器为 16 bit；是否增加 12-bit 紧凑 DDR/BRAM 打包由带宽、BRAM和控制代价实验决定。 | A/Y |
| MEM-003 | P0 | P | 激活主布局为通道按 8 补齐的 `NHWC8`；权重主布局为与 `Pout=8, Pin=8` 匹配的 block 格式。 | S/A |
| MEM-004 | P0 | C | DMA 必须自动拆分不能跨越 4 KiB 边界的 burst，并正确处理 AXI back-pressure 和错误响应。 | S/B |
| MEM-005 | P0 | P | 外部数据地址至少 64-byte 对齐；尾块由有效字节数或 byte strobe 处理，不得访问分配区外。 | S/B |
| MEM-006 | P0 | C | 权重/激活 DMA 至少双缓冲，使下一 tile 传输可与当前 tile 计算重叠。 | S/Y/B |
| MEM-007 | P0 | C | 编译器必须做张量生命周期和片上容量检查；无法映射时必须显式报错，不能在硬件中覆盖活跃张量。 | S |
| MEM-008 | P1 | P | DMA 支持二维 stride 传输，以降低非连续 tile 的命令数量。 | S/B |

|---|---|---|---|---|
| IF-001 | P0 | C | 控制/状态通过 AXI4-Lite 从 PS 访问。 | S/B |
| IF-002 | P0 | P | DDR 数据访问由 PL `M_AXI` 连接一个 PS `S_AXI_HP` 口，首版数据宽度 64 bit。 | Y/B |
| IF-003 | P0 | C | 完成和错误均支持中断；轮询仍可用。 | S/B |
| IF-004 | P0 | P | 寄存器接口必须提供 capability、ISA 版本、实现版本和错误信息，驱动在提交前检查兼容性。 | S/B |
| IF-005 | P0 | C | 所有外部内存数据与寄存器采用小端语义。 | S/B |
| SW-001 | P0 | C | 交付物必须包含图/权重打包器、命令生成器、驱动接口和位精确参考模拟器。 | I/S/B |
| SW-002 | P0 | P | 模型包包含 magic、schema/ISA 版本、区段长度、图哈希和完整性校验；不直接保存绝对主机路径。 | I/S |
| SW-003 | P0 | C | 当前导出的 OIHW/float scale 包只是算法参考；硬件部署前必须重排权重并把浮点 scale 编译为整数参数。 | I/S |

## 8. 性能与实时性

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| PERF-001 | P0 | C | 当前网络单个 16 帧块从任务开始到 Tensor 输出完成必须小于 46 ms，提供至少 2× 相对 92.88 ms 音频块的余量。 | A/S/B |
| PERF-002 | P0 | P | 当前网络任务总周期目标不超过 4,000,000 cycle，包含命令、DMA 等待和计算，不含 STFT/iSTFT。 | A/S/B |
| PERF-003 | P0 | P | PL 实现最低验收时钟为 100 MHz；目标实现时钟为 200 MHz。若最终系统时钟不同，仍必须满足 PERF-001。 | Y/B |
| PERF-004 | P0 | C | 连续实时运行不得出现 deadline miss、DMA 数据损坏或输入/输出 FIFO 溢出。 | B |
| PERF-005 | P0 | P | 至少记录任务周期、计算忙周期、DMA 等待周期、读写字节数和各 FIFO 高水位。 | S/B |
| PERF-006 | P1 | P | 对每个编译后的网络，工具必须报告估计周期、峰值片上空间和 DDR 流量，并与 RTL/板上计数器校准。 | A/S/B |

## 9. 资源、时序与可靠性

| ID | 优先级 | 状态 | 需求 | 验证 |
|---|---|---|---|---|
| RES-001 | P0 | P | NPU 核资源上限为 DSP48E1 ≤112、BRAM36 ≤112、LUT ≤40,000、FF ≤70,000，给 FFT、音频 I/O 和系统互连留余量。 | Y |
| RES-002 | P0 | P | 首版 MAC 阵列基线为 64 lane；扩到 128 lane 只能在真实周期模型显示必要且实现预算允许后进行。 | A/Y |
| RES-003 | P0 | C | 布局布线后的时序结果而非综合估计决定频率验收；P0 时钟路径不得有负 slack。 | Y |
| REL-001 | P0 | C | 异步复位释放、PS/PL 时钟域、AXI 和音频相关跨时钟路径必须经过 CDC 检查。 | Y |
| REL-002 | P0 | P | watchdog 超时、非法命令、DMA 错误和描述符错误必须锁存首个错误码、错误 PC 和任务 tag，直到软件清除。 | S/B |
| REL-003 | P0 | C | 软复位只能清空 NPU 内部任务状态，不得发出新的 DDR 写事务；复位完成后可重新提交任务。 | S/B |
| REL-004 | P0 | C | 上板连续运行至少 30 分钟，输出序号连续且错误计数为 0。 | B |

## 10. P1 退出条件

P1 需求基线只有在以下项目完成后才能标记为冻结：

1. `SYS-007` 的实际板卡、DDR、速度等级和工具版本已确认；
2. P0 要求不存在未解释的相互冲突；
3. 每条 P0 要求已有明确验证方法和负责人；
4. 当前模型的算子、shape、量化和生命周期清单已由工具生成并复核；
5. 第二个验通用性的模型已经选定；
6. 所有“待确认”项已转为“已确认”、降级为 P1/P2，或明确移出 v1。
